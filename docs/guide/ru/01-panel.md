# Панель Clomni

Каждое приложение в Clomni — это отдельный канал «Mobile app (App SDK)». В этой главе канал создаётся, а затем
показано, где находится каждая настройка. Для этого нужна роль Administrator в аккаунте Clomni.

> Это руководство есть и в панели: страница канала → боковое меню → **Guide**. См. [Guide](#guide).

## Создание канала

1. Откройте **Settings** (шестерёнка на левой панели) → **Workspace settings** → **Inboxes** → **Add Inbox**.
2. Откроется каталог каналов. Найдите карточку **Mobile app (App SDK)** и нажмите **Connect**.

![Карточка Mobile app (App SDK) в каталоге каналов](../images/panel-catalog-en.png)

В мастере шесть шагов. Обязателен только первый; остальные можно пропустить кнопкой **Do it later** и закончить
позже на странице канала.

### Шаг 1. Данные приложения

![Шаг 1 мастера: название, платформы, имя пакета, Bundle ID](../images/panel-wizard-en.png)

1. **Channel name**: название, которое операторы видят в списке каналов, например «Example app».
2. **Platforms**: отметьте платформы, на которых работает приложение.
3. **Android package name**: `applicationId` из `app/build.gradle(.kts)`, например `com.example.app`.
4. **iOS Bundle ID**: Bundle Identifier таргета приложения в Xcode (Signing & Capabilities).
5. **Create**. Канал и его ключи создаются сразу.

### Шаг 2. Установка

На этом шаге видны **App ID** и **API-ключи** каждой платформы, рядом — готовый код для копирования.

> **Скопируйте API-ключи сейчас.** Полностью они показываются только на этом шаге. Потом панель показывает лишь
> начало ключа. Если ключ потерян, создайте новый в разделе **Installation** (см. ниже).

### Шаг 3. Identity verification

На этом шаге показывается **Identity Secret** — только один раз.

- Сразу сохраните его на сервере, например в переменной окружения `CLOMNI_IDENTITY_SECRET`.
- Никогда не кладите его в приложение.
- Чтобы продолжить, отметьте «I have stored the secret safely».
- Выберите режим. Пока оставьте **Recommended**. Режимы описаны в главе
  [Идентификация пользователей](02-identity.md).

### Шаг 4. Push-уведомления

Загрузите JSON-файл service account Firebase (Android) и ключ APNs `.p8` (iOS) или нажмите **Do it later**. Где
взять эти файлы: [Ключи для push](08-push-keys.md).

### Шаг 5. Внешний вид

Основной цвет, логотип, приветствие, тема и плавающая кнопка. Начальные значения берутся из чата на вашем сайте.
Всё остальное — в разделе **Appearance**.

### Шаг 6. Сценарии

Выберите сценарий, который запускается, когда пользователь начинает новый диалог. Он копируется в этот канал как
черновик. Опубликуйте его в разделе **Flows**, иначе Messenger не будет его выполнять.

## Страница канала

Позже канал открывается через **Settings → Workspace settings → Inboxes**. Настройки канала находятся в отдельной
колонке рядом с боковой панелью: вверху **← Inboxes** и название канала, ниже — разделы в трёх группах. Для SDK
нужны:

| Группа | Раздел | Что там |
|---|---|---|
| APP | Overview | Состояние канала, предупреждения, последние устройства |
| | Installation | App ID, API-ключи, код для каждой платформы, последние устройства |
| | Security | Режим Identity verification, Identity Secret, проверка хеша |
| | Push | Ключи Firebase и APNs, заголовок уведомления, тестовый push |
| | Guide | Это руководство в PDF и пакет для каждой платформы |
| MESSENGER | Appearance | Цвета, логотип, тексты, языки, карточки главного экрана, тема |
| | Flows | Сценарии этого канала, по тому, что их запускает |
| | News | Новости на главном экране Messenger |
| INBOX | Analytics | Активные устройства, диалоги, push-уведомления, версии SDK |

В группе INBOX есть и настройки, общие для всех каналов: основные параметры, сотрудники, рабочие часы. На снимках
открытый раздел меню обведён красной рамкой. На узком экране меню превращается в выпадающий список над страницей.

### Overview

![Раздел Overview с предупреждением](../images/panel-overview-en.png)

Первое место, куда стоит смотреть, если что-то не работает. Для каждой платформы видно, подключился ли SDK и включены
ли push-уведомления. Предупреждения (1) называют проблему прямо, например входы, отклонённые из-за неверного хеша.
**Fix** открывает раздел, где проблема решается.

### Installation: App ID и API-ключи

![Installation: API-ключи](../images/panel-install-keys-en.png)

- **API keys** (1): App ID с кнопкой **Copy**, затем ключи каждой платформы. От ключа видно только начало.
- **New key** (2) создаёт новый ключ для этой платформы и один раз показывает его целиком.
  - Предыдущий ключ работает ещё **7 дней**. После этого версии приложения со старым ключом не смогут подключиться.
  - Создавайте новый ключ, только если старый утёк, или вместе с релизом, который установит большинство
    пользователей.
- **Revoke** сразу отключает ключ. Используйте его для утёкшего ключа.

Ниже, в блоке **Code**, есть готовый код для Android, iOS, React Native и Flutter с уже подставленным App ID.

![Installation: код для каждой платформы](../images/panel-install-code-en.png)

**Recent devices** показывает последние подключившиеся устройства с версией приложения и SDK. Устройство появляется
здесь через несколько секунд после того, как приложение вызвало `initialize` и открыло сессию.

### Security

![Security](../images/panel-security-en.png)

1. **Mode**: Off, Recommended или Enforced. См. [Идентификация пользователей](02-identity.md#режимы).
2. **Make a new secret**: новый secret показывается один раз. Старый работает ещё 7 дней — за это время переведите
   сервер на новый.
3. **Test a hash**: введите `user_id` и `user_hash`, который выдал ваш сервер. Панель скажет, совпадает ли он с
   текущим secret, со старым или ни с одним.

### Push

![Push: ключи Firebase и APNs](../images/panel-push-en.png)

1. **Android · Firebase Cloud Messaging**: JSON-файл service account проекта Firebase.
2. **iOS · Apple Push Notification service**: ключ `.p8` вместе с Key ID, Team ID и Bundle ID.

Как получить и загрузить оба: [Ключи для push](08-push-keys.md).

Под ключами:

- **Last 7 days**: отправленные, неудачные, с удалённым токеном (приложение удалено с устройства) и пропущенные (нет
  ключа для этой платформы) push-уведомления.
- **Notification title**: что написано в первой строке уведомления. По умолчанию «Оператор · Бренд».
- **Test push**: см. ниже.

#### Test push

![Test push](../images/panel-push-test-en.png)

1. **Device**: выберите одно из устройств, приславших push-токен. В списке указаны платформа, модель, версия
   приложения и окружение APNs (sandbox или production).
2. **Send**. Ответ под кнопкой — это ответ самого FCM или APNs. «Sent» значит, что уведомление должно появиться на
   устройстве.

Список пуст, пока приложение не вызовет `setDeviceToken` на телефоне, где разрешены уведомления.

### Appearance

![Appearance](../images/panel-appearance-en.png)

Изменения сохраняются в черновике. Приложения видят только опубликованную версию.

1. **Publish** отправляет черновик в приложения. Открытые Messenger обновляются прямо на экране, новый релиз
   приложения не нужен. Кнопка **Versions** рядом возвращает одну из прежних версий.
2. **Main colour** и остальные настройки блока Brand: название, шапка, логотип. Превью справа сразу показывает каждое
   изменение.

Блок **Languages** задаёт, на каких языках говорит Messenger. Приложение может выбрать один из них через
`setLanguage`; если не выбрало, Messenger подстраивается под язык телефона.

![Appearance: языки](../images/panel-appearance-languages-en.png)

В блоке **Theme** — режим (1: как в системе, светлая, тёмная), звуки сообщений и плавающая кнопка (2) с её
положением и отступом снизу. Значение, заданное приложением в коде (`setTheme`, `setLauncherVisible`), важнее
настройки в панели.

![Appearance: тема и плавающая кнопка](../images/panel-appearance-theme-en.png)

### Flows

![Flows](../images/panel-flows-en.png)

Сценарии этого канала сгруппированы по тому, что их запускает:

- **When a conversation starts**: сценарий, который встречает новый диалог.
- **App event** (1): сценарии, которые приложение запускает через `startFlow`. У каждого указано имя события,
  например `Event: ride_problem`, и код, который его отправляет.
- **By hand**: сценарии, которые оператор сам отправляет в диалог.

**Open the builder** (2) открывает конструктор сценариев Clomni. Чтобы сценарий запускался событием приложения,
выберите триггер «App event», впишите имя события и опубликуйте сценарий.

### News

![News](../images/panel-news-en.png)

Новости показываются на главном экране Messenger: первые три опубликованные. **New item** (1) создаёт новость с
обложкой, заголовком, кратким и полным текстом и, при желании, кнопкой. Кнопка может открывать веб-адрес или
deep link вашего приложения (см. `onLink` в главе вашей платформы).

### Guide

![Guide](../images/panel-guide-en.png)

Это руководство есть и в панели.

1. Руководство в PDF на четырёх языках: азербайджанском, английском, турецком и русском. Язык панели идёт первым.
2. **Online guide language**: ссылки ниже открывают главы руководства на этом языке.
3. **Online guide** открывает главу для вашей платформы. В карточке есть команда установки пакета — скопируйте её
   кнопкой **Copy**.
