# Clomni Mobile SDK: руководство по интеграции

Clomni Mobile SDK открывает Clomni Messenger прямо внутри вашего приложения для iOS или Android. Пользователи пишут
в поддержку, не выходя из приложения, а обращения попадают к вашим операторам в Clomni — туда же, где WhatsApp,
Instagram и чат на сайте.

![Messenger внутри приложения: главный экран, выбор языка, шаг сценария и ответ оператора](../images/sdk-screens.png)

*Снимки экрана в этом руководстве сделаны в Android SDK. iOS SDK показывает те же экраны.*

*Интерфейс панели Clomni доступен на азербайджанском и английском языках. Снимки панели и названия кнопок в этом
руководстве приведены по английской версии.*

## Что делает SDK

- Открывает Messenger на нативных экранах, без WebView.
- Выполняет ваши сценарии Clomni с нативными кнопками: выбор языка, меню, формы, передача оператору.
- Показывает ответы push-уведомлениями, когда приложение закрыто.
- Берёт цвета, логотип, тексты и новости из панели Clomni. Изменение в панели доходит до приложения без нового
  релиза.

Сам по себе SDK ничего не добавляет на ваши экраны. Messenger открывается из вашей собственной кнопки, например из
строки «Поддержка» на экране профиля. Есть и плавающая кнопка, но она не видна, пока вы её не включите.

## Пакеты

| Платформа | Пакет | Минимальные требования |
|---|---|---|
| Android | `ai.clomni:messenger:1.0.2` (Maven Central) | Android 6.0 (API 23), Kotlin 1.8 |
| iOS | Swift Package `https://github.com/clomni/clomni-mobile-sdk.git`, версия 1.0.2, продукт `ClomniMessenger` | iOS 15, Xcode 15 |
| React Native | `@clomni/react-native` | React Native 0.75 |
| Flutter | `clomni_flutter` | Flutter 3.16, iOS 15, Android API 24 |
| Unity | `https://github.com/clomni/clomni-mobile-sdk.git?path=unity#unity-1.0.2` | Unity 2021.3, iOS 15, Android API 23 |

React Native, Flutter и Unity работают поверх нативных SDK для Android и iOS, поэтому всё описанное в руководстве
одинаково работает на всех платформах.

SDK обращается к `https://app.clomni.ai/v1` по HTTPS и через WebSocket на том же хосте. Если корпоративная сеть или
MDM-профиль разрешают только хосты из списка, добавьте этот хост.

## Порядок действий

1. **В панели Clomni** создайте канал «Mobile app (App SDK)». Вы получите App ID, API-ключ для каждой платформы и
   Identity Secret. См. [Панель Clomni](01-panel.md).
2. **На своём сервере** вычисляйте `user_hash` для каждого вошедшего пользователя с помощью Identity Secret. См.
   [Идентификация пользователей](02-identity.md).
3. **В приложении** подключите пакет, вызовите `initialize` при запуске, авторизуйте пользователя и откройте
   Messenger из своей кнопки. См. раздел для вашей платформы:
   [Android](03-android.md), [iOS](04-ios.md), [React Native](05-react-native.md), [Flutter](06-flutter.md),
   [Unity](07-unity.md).
4. **Push-уведомления**: загрузите ключи Firebase и APNs в панель ([Ключи для push](08-push-keys.md)) и передайте
   токен устройства в SDK (раздел о push в главе вашей платформы).
5. **Проверьте** работу через «Test push» и **Overview** в панели. Если что-то не работает, см.
   [Решение проблем](09-troubleshooting.md).

## Ключи

| Ключ | Как выглядит | Где хранится |
|---|---|---|
| App ID | `app_…` | В приложении |
| API-ключ Android | `android_…` | В Android-приложении |
| API-ключ iOS | `ios_…` | В iOS-приложении |
| Identity Secret | длинная случайная строка | **Только на вашем сервере.** Никогда не в приложении |

API-ключ привязан к одной платформе: ключ iOS не работает в Android-приложении. Приложения на React Native, Flutter и
Unity передают ключ той платформы, на которой запущены.

## Термины

- **Канал (inbox)**: одно приложение в Clomni. Его сообщения, ключи и настройки хранятся вместе.
- **Источник (source)**: короткое имя, которое вы передаёте при открытии Messenger, например `profile_support`. Оно
  сохраняется вместе с начатым там диалогом и видно в статистике панели.
- **Сценарий (flow)**: автоматический диалог, собранный в конструкторе сценариев Clomni: кнопки, вопросы, передача
  оператору.
- **Событие приложения (App event)**: имя вроде `ride_problem`, которое приложение отправляет через `startFlow`.
  Опубликованный сценарий, привязанный к этому событию, начинает диалог на эту тему.
